1. Interrogating data locally

In this week, you will be using your laptops to work with a relatively big research dataset to answer actual research questions that arose from a research project.

Session’s goals

  1. Familiarise with the dataset (and the process it represents)
  2. learn tidyverse’s syntax for frequent data manipulations:
    1. filter() to subset rows matching some conditions
    2. select(), to subset columns (by name or position)
    3. group() and summarise() to compute summaries based on some criteria
    4. join_by() to combine datasets
  3. learn when to apply these methods to address research questions

The data

The data consists of two csv files:

  1. proposals.csv: containing all Approved, Rejected and Proposed tagging proposals from the OSM Wiki, as well as their associated metadata.

  2. proposals_votes.csv: containing all the votes cast for every tagging proposal in proposals.

Both files were generated using a dedicated R-package called {OSMproposals} (Cámara-Menoyo 2026) which provides reproducible datasets containing information about OpenStreetMap’s tagging proposals. It does so by querying and webscrapping OSM’s wiki via helper functions. Refer to the official documentation page: https://warwickcim.github.io/osmproposals/ to see metadata and the source code that generated each dataset.

Cámara-Menoyo, Carlos. 2026. OSMpRoposals: Reproducible Datasets about OpenStreetMap’s Tagging Proposals. https://warwickcim.github.io/osmproposals/.
WarningImportant considerations

  2. These datasets are part of an ongoing research. Please, do not share them beyond the classroom unless with explicit permission from their authors.

Fixing data

To fix the problem we detected, we need to change draft_started column type to a date, and we will be using mutate() to do so.

NoteHint 1

We are looking for a column name here. We need to write the name of the column that we want to convert to a date.

TipFully worked solution: 
proposals <- mutate(proposals, draft_started = as.Date(draft_started))
Tip

Note that this syntax would be equivalent to base R’s syntax:

proposals$draft_started <- as.Date(proposals$draft_started)

At this moment tidyverse syntax may seem a little bit confusing and not very useful, but maybe the next bits can change our minds.

But actually, it’s more common to write this code using the pipe operator1 |>:

1 This operator allows for chaining multiple operations together, streamlining code.
The pipe operator (|>) takes the value of its left-hand side to the first argument of the function on its right-hand side. This enables a natural and readable way of chaining multiple functions together, reducing the need for intermediate variables and improving code clarity.

# Nested, reads inside-out
round(mean(log(c(10, 100, 1000))), 2)
[1] 4.61
# Piped, reads left to right
c(10, 100, 1000) |> log() |> mean() |> round(2)
[1] 4.61
Important

Bear with me: we will see why this syntax using the pipe operator |> is very convenient.

How much labour is required to make a proposal?

Again, there are multiple ways to define labour. One way could be to count time spent since their initial draft until the end of the voting process.

Important

Only a subset of proposals ever get to get voted, so we are going to use filter() to subset those proposals whose status is either Approved or Rejected and only select() the columns that are needed.

Here, we will be using select() to subset columns:

# Let's subset only the columns that are needed time_spent_completed <- proposals |> select(title, status_raw, draft_started, vote_end) glimpse(time_spent_completed) 

# Let's subset only the columns that are needed
time_spent_completed <- proposals |> 
  select(title, status_raw, draft_started, vote_end)

glimpse(time_spent_completed)

And now, let’s use filter() to subset rows whose status is either “Approved” or “Rejected”:

# Let's subset only the rows that are needed time_spent_completed <- time_spent_completed |> filter(status_raw %in% c("Approved", "Rejected")) glimpse(time_spent_completed) 
# Let's subset only the rows that are needed
time_spent_completed <- time_spent_completed |> 
  filter(status_raw %in% c("Approved", "Rejected"))

glimpse(time_spent_completed)

And now, we are going to compute the amount of time spent. We will be using mutate() to create a new variable called time_spent which is the time difference between the proposal was voted (finished) and drafted (started).

time_spent_completed <- time_spent_completed |> mutate(time_spent = vote_end - draft_started) time_spent_completed 
time_spent_completed <- time_spent_completed |> 
  mutate(time_spent = vote_end - draft_started)
  
time_spent_completed

ImportantWide vs long data3

proposals_votes is a long dataset (as opposed to a wide one, like the previous one):

  • wide datasets: each row is an observation, refers to a unique value

  • long dataset: multiple rows refer to a same observation
