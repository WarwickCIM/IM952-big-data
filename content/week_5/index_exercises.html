Week 5: Data

In this week, you will be using your laptops to work with a relatively big research dataset (Cámara-Menoyo 2026) to answer actual research questions that arose from a research project.

Session’s goals

  1. Familiarise with the dataset (and the process it represents)
  2. learn tidyverse’s syntax for frequent data manipulations:
    1. filter() to subset rows matching some conditions
    2. select(), to subset columns (by name or position)
    3. group() and summarise() to compute summaries based on some criteria
    4. join_by() to combine datasets
  3. learn when to apply these methods to address research questions

The data

The data consists of two csv files:

  1. proposals.csv: containing all Approved, Rejected and Proposed tagging proposals from the OSM Wiki, as well as their associated metadata.

  2. proposals_votes.csv: containing all the votes cast for every tagging proposal in proposals.

Both files were generated using a dedicated R-package called {OSMproposals} (Cámara-Menoyo 2026) which provides reproducible datasets containing information about OpenStreetMap’s tagging proposals. It does so by querying and webscrapping OSM’s wiki via helper functions. Refer to the official documentation page: https://warwickcim.github.io/osmproposals/ to see metadata and the source code that generated each dataset.

WarningImportant considerations
  1. The provided datasets contain experimental versions of the actual datasets provided by the package, so documentation may slightly differ.
  2. These datasets are part of an ongoing research. Please, do not share them beyond the classroom unless with explicit permission from their authors.

# One way could be to count time spent since their initial draft until the end
# of the voting process.

# Only a subset of proposals ever get to get voted, so we are going to use
# filter to subset those proposals whose status is either approved or rejected
# and only select the columns that are needed.

# Let's subset only the columns that are needed
time_spent_completed <- proposals |> 
  select(title, status_raw, draft_started, vote_end)


time_spent_completed

# Let's subset only the rows that are needed
time_spent_completed <- time_spent_completed |> 
  filter(status_raw %in% c("Approved", "Rejected"))


View(time_spent_completed)

# And now, we are going to compute the amount of time  spent. We will be
# creating a new variable called `time_spent` which is the time difference
# between the proposal was voted (finished) and drafted (started)

time_spent_completed <- time_spent_completed |> 
  mutate(time_spent = vote_end - draft_started)

View(time_spent_completed)


# TIP: Remember when we spoke about the pipe operator |> ? We could pipe those
# two verbs in a single expression!
time_spent_completed_piped <- proposals |> 
  select(title, status_raw, draft_started, vote_end) |> 
  filter(status_raw %in% c("Approved", "Rejected")) |> 
  mutate(time_spent = vote_end - draft_started)

# Let's see if these two dataframes are identical:
all.equal(time_spent_completed, time_spent_completed_piped)

# This column says how much time each proposal took. We would need to have some
# nice summary statistics to have a good overview of the process.
summary(time_spent_completed$time_spent)

# WARNING: we have some results that are either missing (NA) or negative values.
# This is because either the draft_started or vote_end values are missing. We
# should get rid of them to before proceeding.

# But what if we wanted to see if there are differences between approved and
# rejected proposals? We will use group_by() and summarise().
time_spent_completed_summaries <- time_spent_completed |> 
  filter(time_spent > 0) |> 
  group_by(status_raw) |> 
  summarise(
    min = min(time_spent),
    first_q = quantile(time_spent, probs = 0.25),
    median = median(time_spent),
    mean = mean(time_spent),
    third_q = quantile(time_spent, probs = 0.75),
    max = max(time_spent)
  )

# Do we spot differences between these two groups?
time_spent_completed_summaries

# How many votes did each proposal receive? -------------------------------

# Votes are stored in a different dataset.
proposals_votes <- as_tibble(proposals_votes)

head(proposals_votes)

# This is a long dataset (as opposed to a wide one, like the previous one):
# - wide datasets: each row is an observation, refers to a unique value
# - long: multiple rows refer to a same observation.

# We could use what we've learnt to count the votes for each proposal and type
# of vote:
proposals_votes_count_long <- proposals_votes |> 
  count(url, vote)

head(proposals_votes_count_long, 10)

# We can remove the proposals with no votes
proposals_votes_count_long <- proposals_votes_count_long |> 
  filter(!is.na(vote)) 


# This format is not very useful for us now. It would be better to see how many
# votes of each type a proposal has received. In other words, we need to convert
# from a long format to a wide format. To do so, we will use another package
# from the tidyverse: tidyr. tidyr provides two convenient functions pivot_wider
# to convert from long to wide, and pivot_longer, to do the opposite.

# Uncomment below if you need to install the package:
# install.packages("tidyr")

proposals_votes_count <-  proposals_votes_count_long |> 
  tidyr::pivot_wider(names_from = vote, values_from = n)

proposals_votes_count

# We have two datasets: one containing proposals, and another one containing
# votes. Wouldn't it be nice to have the total votes per proposal in a single
# dataset?

# To combine proposals with proposals_votes, we need to:
# 1. Make sure that both dataframes have a shared field to use as an index
# 2. Make sure that both dataframes are either long or wide

proposals <- proposals |> 
  left_join(votes_count, by = join_by(fullurl == url))
  

# Or we could do all of this (and something more) in one statement 
votes_count <- proposals_votes |>
  filter(!is.na(vote)) |>
  count(url, vote) |>
  tidyr::pivot_wider(names_from = vote, values_from = n) |>
  mutate(
    votes_total = rowSums(
      across(c(Approve, Oppose, Abstain, Other)),
      na.rm = TRUE
    )
  ) |>
  rename(
    votes_approve = Approve,
    votes_oppose = Oppose,
    votes_abstain = Abstain,
    votes_other = Other
  )


proposals <- proposals |> 
  # Incorporate votes
  left_join(votes_count, by = join_by(fullurl == url))
